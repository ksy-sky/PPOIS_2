# Отчет по лабораторной работе №2
## Проектирование программного обеспечения интеллектуальных систем (часть 2)

### Тема: Разработка приложения с графическим интерфейсом для учета студентов

---


### Компоненты MVC

**Model (Модель)** представлена классами `Student` и `Database`. Класс `Student` описывает структуру записи с полями согласно варианту задания: ФИО студента, ФИО отца, заработок отца, ФИО матери, заработок матери, число братьев, число сестер. Класс `Database` инкапсулирует все операции с базой данных SQLite: создание таблицы, добавление, поиск, удаление, пагинацию.

**View (Представление)** включает все классы, отвечающие за отображение информации и взаимодействие с пользователем. Главное окно содержит меню, панель инструментов, таблицу для отображения записей, древовидное представление и элементы управления пагинацией. Отдельные диалоговые окна реализуют операции добавления, поиска и удаления.

**Controller (Контроллер)** выступает связующим звеном между моделью и представлением. Он обрабатывает действия пользователя (нажатия кнопок, выбор пунктов меню), вызывает соответствующие методы модели и обновляет представление.

## 1. Реализация функциональных требований

### 1.1 Главное окно и навигация

Главное окно приложения содержит меню с тремя разделами: "Файл" (операции с XML), "Записи" (добавление, поиск, удаление) и "Вид" (переключение между таблицей и деревом). Все команды меню продублированы на панели инструментов для удобства доступа.

В центральной части окна отображаются записи из базы данных. Реализовано два режима просмотра:
- **Табличный режим** - компактное отображение всех полей в виде таблицы
- **Древовидный режим** - иерархическое представление, где каждый студент является корневым элементом, а его родители и количество братьев/сестер - дочерними

### 1.2 Пагинация

Одним из ключевых требований являлась реализация постраничного вывода записей как в главном окне, так и в диалоге поиска. Для этого были разработаны следующие элементы управления:
- Кнопки перехода: первая страница, предыдущая, следующая, последняя
- Выпадающий список для выбора количества записей на странице (5, 10, 25, 50, 100)
- Информационные метки, показывающие текущую страницу, общее количество страниц и общее количество записей

Пагинация реализована на уровне базы данных с использованием SQL-операторов LIMIT и OFFSET, что обеспечивает эффективную загрузку только необходимых записей.

### 1.3 Работа с базой данных

В качестве СУБД использована SQLite, что не требует установки отдельного сервера и идеально подходит для настольных приложений. Таблица students содержит следующие поля с правильными типами данных:
- `student_name` (TEXT) - ФИО студента
- `father_name` (TEXT) - ФИО отца
- `father_income` (REAL) - заработок отца
- `mother_name` (TEXT) - ФИО матери
- `mother_income` (REAL) - заработок матери
- `brothers` (INTEGER) - число братьев
- `sisters` (INTEGER) - число сестер

### 1.4 Диалог добавления

Диалог добавления содержит поля для ввода всех атрибутов студента. Реализована валидация ввода:
- Поля с числами (заработок, количество братьев/сестер) принимают только цифры
- Поле ФИО студента является обязательным
- Все поля используют соответствующие типы данных Python (str, int, float)

### 1.5 Диалог поиска

Особое внимание было уделено реализации поиска в соответствии с вариантом задания. Диалог поиска содержит:

**Условия поиска по ФИО студента:**
Три отдельных поля (фамилия, имя, отчество) с ограничением - может быть заполнено только одно. Это соответствует требованию "Может быть заполнен только один элемент ФИО, например имя". При попытке заполнить второе поле выдается предупреждение и поля очищаются.

**Условия поиска по ФИО родителя:**
Аналогичная логика с выбором родителя (отец/мать) и тремя полями ФИО, где также может быть заполнено только одно.

**Условия поиска по числу братьев или сестер:**
Радиокнопки для выбора типа (братья/сестры) и числовое поле для ввода количества.

**Условия поиска по заработку родителя:**
Выбор родителя (отец/мать) и два поля для задания диапазона (от и до). Можно заполнить как оба поля, так и только одно из них.

**Вывод результатов:**
Результаты поиска отображаются в этом же диалоговом окне в таблице с собственной пагинацией. Пользователь может переключать страницы результатов, менять количество записей на странице, видеть общее количество найденных записей.

### 1.6 Диалог удаления

Диалог удаления использует те же условия, что и диалог поиска, но с важным отличием: перед фактическим удалением пользователю показывается предпросмотр записей, которые будут удалены. Отображается список студентов (до 10) и общее количество найденных записей. Это предотвращает случайное удаление данных.

После подтверждения выполняется удаление, и пользователь получает сообщение о количестве удаленных записей.

### 1.7 Работа с XML

Реализована поддержка формата XML с использованием двух различных парсеров согласно требованию:

**Сохранение (DOM парсер):**
Для экспорта данных используется DOM-парсер из модуля xml.dom.minidom. Это позволяет создать структурированный XML-документ с красивым форматированием, где каждый студент представлен отдельным элементом `<student>`, а его поля - вложенными элементами.

**Загрузка (SAX парсер):**
Для импорта данных используется SAX-парсер, который обрабатывает XML-документ последовательно, не загружая его целиком в память. Это более эффективно для больших файлов. При парсинге создаются объекты Student и добавляются в базу данных.
